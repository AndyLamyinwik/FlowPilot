# FlowPilot v0.1.0

**Draft release notes — unreleased Early Public Release candidate.** No release date, tag, image publication, or GitHub Release is established by this document. The current release decision is **NOT_READY**; consult the [release checklist](../RELEASE_CHECKLIST.md) before publishing.

## Overview

FlowPilot is a lightweight, self-hosted workflow automation platform with a visual node editor. This first candidate focuses on understandable workflow editing, deterministic execution, local persistence, and an optional extension boundary for future AI providers. It is an early public test candidate, not an enterprise-stable release.

## Highlights

- Visual workflow editing with drag-and-drop nodes, connections, configuration, and Explicit Save.
- Manual and scheduled workflows using the same execution service and engine.
- HTTP requests, conditional branches, JSON transformation, outgoing webhooks, and logging nodes.
- Execution results, per-node status, paginated history, and persistent SQLite data.
- Production frontend resources served by a small Node server with a same-origin API proxy.
- An independently testable AI Provider Foundation with a deterministic offline Mock only.

Local automated and native integration evidence exists for the core features. Docker configuration has been checked, but actual container build/startup/recreation and remote CI still require validation. GitHub Private Vulnerability Reporting is enabled; its saved setting and public entry were verified on 2026-10-30, without submitting a report or testing notification delivery.

## Installation

The intended container setup requires Git and Docker Engine/Desktop with Compose. Clone the current candidate source from [AndyLamyinwik/FlowPilot](https://github.com/AndyLamyinwik/FlowPilot). A versioned `v0.1.0` tag and published GitHub Release are not yet available:

```bash
git clone https://github.com/AndyLamyinwik/FlowPilot.git flowpilot
cd flowpilot
cp .env.example .env
docker compose config --quiet
docker compose up -d --build --wait
```

On Windows PowerShell, use `Copy-Item .env.example .env`. Preserve an existing `.env` instead of overwriting it. These are the prepared deployment instructions; **Docker runtime acceptance is not yet complete**.

Access the [frontend](http://localhost:5173), [backend health API](http://127.0.0.1:8000/api/health), and [Swagger UI](http://127.0.0.1:8000/docs). Default port publication is loopback-only. See the [README](../../README.md) for native development, configuration, troubleshooting, and safe backup/restart guidance.

The [workflow examples](../../examples/workflows/README.md) cover Manual Logger, Scheduled Logger, and an API/Condition flow. Scheduled examples remain disabled after creation until explicitly enabled. HTTP examples require destination setup; structural validity alone is not execution readiness.

## AI Status

Only the interface and Mock Provider are implemented. There are no built-in real OpenAI, Anthropic/Claude, Gemini, or Ollama calls, AI workflow nodes, model downloads, or public AI API.

`FLOWPILOT_AI_ENABLED=false` is the default. Setting it to true does not register providers or activate a real model. Mock responses are fixed, clearly labeled, and do not represent model-generated output or real token usage. See the [AI Provider Guide](../AI_PROVIDER_GUIDE.md).

## Known Limitations

- **No built-in user authentication.** Use a local/trusted environment; do not expose the application directly to the public Internet. An external proxy needs operator-managed authentication, TLS, and network controls.
- **Single-instance scheduler and SQLite persistence.** Use one backend process/worker and scheduler owner per database. There is no distributed execution or Exactly-Once guarantee.
- **Deployment verification is incomplete.** Docker image build, startup, volume permissions, container recreation, and remote GitHub Actions are not yet confirmed.
- **Private reporting verification is bounded.** GitHub's enabled setting and public reporting entry are verified, but no report/advisory submission, notification delivery, or actual receipt was tested. See [SECURITY.md](../../SECURITY.md).
- **AI provider integrations are not available.** The optional Foundation is not an AI workflow system.
- **Execution is synchronous.** There is no live node streaming or cancel API; network loss does not prove that backend execution or an external effect stopped.
- **History is bounded and privacy-oriented.** Outputs are excluded by default; optional basic redaction cannot detect every secret, and historical records are not complete workflow snapshots.
- **Three P2 issues remain.** Browser-unsafe integer configuration can block a workflow list, stale result selection can be affected after a node is deleted, and an extreme history offset can return a controlled 500. Details and workarounds are in the [audit](../PHASE_07A_AUDIT.md).
- **HTTP controls have limits.** The allowlist and DNS/IP checks do not replace network egress policy, and synchronous DNS/I/O is not a hard wall-clock deadline.
